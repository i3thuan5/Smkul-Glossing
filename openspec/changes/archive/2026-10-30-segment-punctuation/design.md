# Design: segment-punctuation

## Context

動機見 proposal.md，要求見 specs/。現況：

- `scripts/smkul/parser.py` 的 `bare_form()` 只留字母、漢字、數字、撇號，族語原句與詞素切割的標點都被去掉，`^` 也被去掉。
- `compare_source()` 另外用 `_punctuation_of()` 比兩行的標點序列，不同就在 `assemble_entry()` 記一筆 `IssueKind.PUNCTUATION_DIFF`（warning）。
- `Severity` 只有三級：`ERROR`（不匯出、影響 exit code）、`WARNING`（照常匯出）、`NOTICE`（不匯出、不算錯）。`Entry.is_clean()` 寫成「不是 WARNING 就不乾淨」。
- `report.render_issue()` 遇到 detail 有半形 `:` 就只留冒號後面那段（給 `分類:差異` 用的）。新的提示會引用 `Yu:m-uwah` 這種語料，會被切壞。
- 全語料（扣掉純華語句）的詞素切割行：103 段有要報錯的標點；199 段有 `+`（273 處，全在泰雅賽考利克）；427 段有詞中間的 `.`（535 處）；46 段有獨立的說話者標記（63 處）。
- 《原住民族語言書寫系統》（113 年修正，`kithann/規範/` 的 PDF）裡，跟這次有關的符號：阿美語 `^` 是喉塞音字母、`:` 是長音符號（`iti:raw`）；泰雅語 `_` 區辨 `n_g` 與弱化央元音（`m_yan`）；賽夏語 `:`；邵語 `.`（`put.huum`）。布農語舊寫法用 `-` 表喉塞音或音節界線，跟切割符號同形，但它本來就是允許的字元，不影響這次的檢查。

## Goals / Non-Goals

**Goals：**

- 一段只記一筆，提示一看就知道是第幾個詞、要怎麼改。
- 「錯誤（照常匯出）」是真正的一級嚴重度，報告、匯出、exit code 三個地方的行為都由它決定，不靠特例。
- 待討論章的 20 段，每次重跑都挑一樣的。

**Non-Goals：**

- 不自動修正 YAML 裡的詞素切割（spec 規定照原樣匯出）。
- 不處理詞素翻譯行的標點。
- 不做校對表，那是 `proofreading-sheet` change。
- 不碰 `features/詞素切割與詞素翻譯對應.feature`。說話者標記會讓詞素切割與詞素翻譯的詞數各多一個，兩邊通常一起多，不影響那邊的判斷。
- 不決定 `+`、詞中間的 `.`、說話者標記要保留還是提示；這次只把它們列進待討論章。

## Decisions

### 決策 1：用黑名單之外的字元判斷標點，不列標點清單

「允許的字元」是 `str.isalnum()`（涵蓋拉丁字母、帶附加符號的字母、漢字、數字）、切割符號 `-=<>~`、撇號 `'`、空白，再加上依族別查表的書寫系統符號；其餘都算標點：

| 族別 | 書寫系統符號 |
|---|---|
| 阿美 | `^` `:` |
| 泰雅 | `_` |
| 賽夏 | `:` |
| 邵 | `.` |

表放在 `parser.py` 的常數，族別用目錄名（`split_kind()` 的結果）。族別不在表裡的就沒有額外符號。

再來是待討論的三種，不算標點、另外收集：

- `+`：一律放行。
- `.`：前後都緊接 `isalnum()` 的字元才算「詞中間」；詞頭、詞尾的 `.` 算標點。邵語的 `.` 已經在上表放行，不會進待討論。
- 獨立的說話者標記：整個詞符合「1 到 3 個 ASCII 字母＋`:` 或 `：`」。整個詞跳過，不再檢查裡面的字元。阿美語的 `:` 雖然放行，`S:` 這種獨立的詞仍然先判成說話者標記。

不另列標點清單（像現在的 `PUNCTUATION` 常數），是因為語料裡出現的 `|`、`@`、`＠` 都不在原本的清單裡，用清單一定會漏。引號在字元正規化那一步已經統一成 `'`，所以不會有 `’` 被誤判。

**替代方案**：沿用 `PUNCTUATION` 常數再補字元。缺點是下次出現新符號又會漏掉，而且會議決議是「不能有標點」，用排除法比較符合決議。

### 決策 2：每個有問題的詞分成三種現象，決定提示怎麼寫

逐個空白分開的詞判斷（獨立的說話者標記已經在決策 1 跳過），第一個符合的就用：

| 現象 | 判斷 | 程式判斷 | 應該寫是 |
|---|---|---|---|
| 符號 | 整個詞沒有任何 `isalnum()` 字元（`＠`、`…`） | 整個詞刪掉 | 整行刪掉這個詞之後的樣子 |
| 括號 | 詞裡有 `()（）` | 無法判斷 | （不寫） |
| 標點 | 其他 | 刪掉 | 刪掉那些字元之後的詞 |

黏在詞前面的說話者標記（泰雅的 `Yu:m-uwah`）照使用者的決定當成一般族語詞：泰雅語不允許 `:`，所以落在「標點」，提示建議刪掉冒號（`Yum-uwah`）。這個建議不一定對，由老師在校對表判斷。

提示裡的「現象」寫實際出現的字元，例如「有標點「,」」、「有標點「?」「.」」（一個詞有好幾種時依出現順序列）。括號寫成一對「()」，不拆成兩個。

**替代方案**：只說「有標點」，不給修改建議。缺點是不符合「能讓人直接找到問題點」的要求，對方還要自己比對。

### 決策 3：新增嚴重度 `Severity.EXPORTED_ERROR = "錯誤（照常匯出）"`，`WARNING` 改名

`Severity.WARNING` 的值從 `"warning"` 改成 `"警告（照常匯出）"`（使用者決定），報告的總覽、章名跟著改。四級是：錯誤、錯誤（照常匯出）、警告（照常匯出）、現象。

`Entry.is_clean()` 改成「沒有 `ERROR`、也沒有 `NOTICE` 才乾淨」（正面列出擋匯出的級別），不再寫成「不是 WARNING 就不乾淨」。exit code 只看 `ERROR`，保持不變。`report.severity_split()` 改成回傳四組，總覽分四行列。

**替代方案 A**：直接放進 `WARNING`，報告把 warning 改叫「錯誤（不擋匯出）」。不行，因為「時間碼格式混用」「時間碼單位不明」spec 明定「不算錯誤」，改名會讓它們被叫成錯誤。

**替代方案 B**：放進 `ERROR` 再在匯出時開特例。不行，exit code、匯出、報告分類三個地方都要開特例，容易漏掉。

### 決策 4：檢查放在 `build_entry()`，比對與標點檢查分開

`compare_source()` 拿掉 `punctuation_differs`，只管逐字比對；新增一支純函式（例如 `check_segment_punctuation(segmentation, ethnic)`）回傳「有問題的詞」清單與待討論的標記（有沒有 `+`、詞中間的 `.`、說話者標記，以及各幾處），feature step 跟 `assemble_entry()` 都用它。檢查放在 `build_entry()`：組好四行、確定不是純華語句之後才檢查，有問題就記一筆 `IssueKind.SEGMENT_PUNCTUATION`（值是「詞素切割有標點」）。純華語句是在 `assemble_entry()` 之後才判斷的，所以不能放在 `assemble_entry()` 裡。`build_entry()` 多一個 `ethnic` 參數，`parse_corpus_file()` 把族別傳進去。

待討論的標記存在 `Entry` 上（例如 `entry.discuss`，一個集合），`validate_glossing.collect()` 走語料時順便收集，不另外再走一次語料。

`bare_form()` 的 `^`：spec 只說阿美語的 `^` 是字母，可是 `bare_form()` 不知道語言。因為阿美以外的語料都沒有 `^`，而且別的語言出現 `^` 時已經會被標點檢查抓到，所以 `bare_form()` 一律保留 `^`，不傳語言進去。`:`、`_`、`.` 照舊去掉（書寫系統說它們是「符號」，不是字母）。分類時 `^` 當一般字母算（「只差一個字母」），不算「只差單引號」。

### 決策 5：`render_issue()` 不再靠冒號切 detail

「族語原句與詞素切割不符」的 detail 是 `分類:差異`，報告只想顯示差異；其他問題的 detail 不應該被切。改成只對 `SOURCE_SEGMENT_MISMATCH` 切，其他種類整串照印，這樣 `G:` 這種語料才不會被切掉。

### 決策 6：待討論章固定挑法

收集時記下（語言別、檔案、段編號、族語原句、詞素切割）。挑法：依「族別/語言別 → 檔案」排序分組，然後輪流從每個檔案拿下一段（round-robin），拿滿 20 段為止。每個檔案裡照段的順序。這樣 `+` 會分散在泰雅的幾個檔案，`.` 與說話者標記會分散在幾個語言別，而且重跑結果一樣。三節用同一支挑選函式。

這一章依照 CLAUDE.md 加章節編號、更新日期由 `report.today()` 產生；語料用 `code()` 包起來，反引號外的逗號用全形。

## Risks / Trade-offs

- [黏在詞前面的說話者標記（泰雅 `Yu:nanu` 等 20 處）會被當成標點錯誤，建議寫法是把冒號刪掉，不一定對] → 提示仍然指出了冒號的位置；老師在校對表判斷。如果承辦決定說話者標記要保留，獨立的跟黏著的可以再一起處理。
- [獨立說話者標記的判斷（1 到 3 個字母加冒號）可能把真正的族語短詞加冒號誤判成說話者] → 這些只進待討論章、不算錯誤，誤判的代價只是多列一段給大家看。
- [說話者標記與對話組（排版分析.feature 的 `@規格要討論`）是同一個現象] → 這次只列進待討論章，對話組另案處理。
- [`^` 一律保留會讓非阿美語的 `^` 同時算標點又算不符] → 目前語料沒有這種情形；真的出現時兩個問題都是真的，請對方改就好。
- [報告的警告章變得很短（只剩時間碼 6 筆）] → 這是預期的；2167 筆「標點不同」本來就是誤報。

## Migration Plan

YAML 結構不變；報告少一類、多一類、多一章。舊報告直接被新報告蓋掉，不用另外轉換。要退回的話就還原這次的程式修改，重新產生報告。
